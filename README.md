# second_brain

> AI(Claude)가 세션과 프로젝트를 거듭하며 똑똑해지도록, 인사이트·삽질·개선안을 쌓는 저장소입니다. 사람(김도하)도 읽고 고칩니다.
> 처음 만든 날: 2026-10-16. 첫 출처: MAGNUM OPUS 프로젝트(`~/MY_PROJECT/making-coolassbitch/magnum-opus/project`)의 2026-10-15~16 세션.

## 읽는 법 (토큰 규칙)

1. **`INDEX.md`만 먼저 읽습니다.** 노트마다 한 줄 요약이 있습니다. 이 저장소 전체를 읽지 않습니다.
2. 지금 일과 관계있는 노트만 엽니다. 긴 노트는 장 하나만 읽습니다(`python3 tools/doc_section.py <노트> <장>`).
3. 새 프로젝트를 시작할 때는 `playbooks/new-project-kickoff.md`부터 봅니다.

## 폴더

| 폴더 | 무엇 |
|---|---|
| `INDEX.md` | 모든 노트의 한 줄 목록 (입구) |
| `insights/` | 일반화한 인사이트: 토큰, 컨텍스트, 문서 구조, 파일 지도 |
| `lessons/` | 삽질과 그 원인, 다시 안 하는 법 |
| `playbooks/` | 따라 하는 절차: 인수인계, 새 프로젝트 시작, 폴더 정리 |
| `templates/` | 그대로 복사해 쓰는 파일: HANDOFF.md, CLAUDE.md, 원문 기록 |
| `tools/` | 다른 프로젝트에 복사해 쓰는 도구와 설명 |
| `ROADMAP.md` | 이 저장소의 목표와 발전 방향 |

## 노트 쓰는 법

- 노트 하나는 주제 하나. 머리에 아래 네 줄을 둡니다.
  ```
  > 날짜: 2026-10-16 · 출처: MAGNUM OPUS · 근거: 측정 | 경험 | 추정 · 태그: 토큰, 세션
  > **규칙:** <다른 프로젝트에서도 통하는 일반 규칙 한 줄> · **적용 범위:** <어떤 프로젝트·상황에 해당하나>
  ```
- **규칙 줄이 먼저, 사례는 아래에.** 한 프로젝트에서만 통하는 사례(숫자, 파일 이름)는 본문에 "사례"로 두고, 머리의 규칙 줄은 다른 프로젝트에서 읽어도 맞게 씁니다(2026-10-17 더함).
- **근거를 구분합니다.** "측정"은 실제 로그·숫자, "경험"은 한 번 겪은 일, "추정"은 아직 확인 안 한 생각입니다. 지어낸 숫자는 쓰지 않습니다.
- 새 노트를 쓰면 `INDEX.md`에 한 줄을 더합니다. 손으로 두 곳을 고치지 말고 `tools/add_note.py`를 씁니다(노트와 INDEX를 함께 고침). 같은 주제의 노트가 이미 있으면 새로 만들지 않고 그 노트를 고칩니다.
- 틀린 것으로 드러나면 지우지 말고 `~~취소선~~`과 날짜, 이유를 남깁니다(왜 틀렸는지도 인사이트).
