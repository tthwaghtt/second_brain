# session-handoff: 끊을 때를 알고, 다음 세션이 헤매지 않게 넘긴다

**왜:** 긴 세션은 응답마다 대화 전체를 다시 읽어 비싸고, 옛 결정과 새 결정이 섞여 틀리게 기억합니다. 끊는 비용은 잘 쓴 상태 문서 한 장입니다.

## 1. 시작할 때

1. 규칙 파일(자동으로 읽힘) → 상태 문서의 "지금"과 "다음 한 걸음" → 그 세션의 "읽을 것" 장만 읽습니다. 그 밖은 필요해질 때 엽니다(`lean-context`).
2. 확인: `git log --oneline -5`, 지금 브랜치, 돌고 있는 작업.
3. 이해한 목표, 할 일, 멈출 곳을 **10줄 이내**로 보고합니다. 승인이 필요하면 기다립니다.
4. "뭐 하던 중이었지?"를 사용자에게 묻지 않습니다. 상태 문서와 git에서 먼저 찾습니다.

## 2. 넘어갈 때를 알아차리기

- **새 세션이 낫다:** 목표를 끝냈다 / 압축이 두 번째다 / 결정을 잘못 기억하는 일이 보인다 / 1시간 넘게 쉬었다 / 다음 일이 다른 목표다.
- **그대로 간다:** 같은 목표 안의 수정과 피드백 반영, 무언가를 기다리는 동안.
- **고를 수 있는 것:** 계속 / 상태 문서를 쓰고 새 세션(기본) / 넓은 탐색은 하위 에이전트에 / 압축(꼭 이어야 할 때만, 압축 전에 결정을 문서에 저장).
- 알아차리고 알려 주는 것까지가 내 일입니다. 끊을지는 사용자가 정합니다.

## 3. 끝낼 때 (순서대로)

1. 이번 세션의 사용자 원문(결정, 피드백)을 원문 기록에 날짜와 함께 덧붙입니다.
2. 결정이 바뀌었으면 기준 문서를 고칩니다(`doc-hygiene` 3장).
3. **상태 문서를 새로 씁니다(덮어씀).** 틀은 `references/status-template.md`입니다. 다른 문서에 있는 내용은 베끼지 말고 "파일 + 장"으로 가리킵니다. 파일 경로, 커밋, 숫자 같은 식별자는 정확히 씁니다.
4. **다음 세션 시작 프롬프트 하나**를 상태 문서 안에 씁니다.
   - 머리에 작성 날짜, 작성한 세션, 다음 세션, 승인 원문의 위치를 적습니다.
   - 승인 문구를 지어내지 않습니다.
   - 그다음 세션들의 프롬프트는 미리 쓰지 않습니다. 앞 세션 결과에 따라 낡기 때문입니다.
   - 다음 할 일이 정해지거나 바뀔 때마다 고칩니다. 세션이 갑자기 끊겨도 맞는 프롬프트가 남아야 합니다.
   - 같은 프롬프트가 다른 문서(로드맵, README)에 있으면 지우고 상태 문서를 가리키게 합니다.
   - 다음 세션의 "읽을 것"은 **장 목록만 보고** 정합니다(`doc_section.py <문서> --list` 또는 제목 grep). 그 장을 지금 읽지 않습니다. 읽는 건 다음 세션의 일이고, 지금 읽으면 이번 세션 맥락만 늘어납니다.
5. **다시 시작 시험:** 상태 문서만 읽고 다섯 가지에 답할 수 있어야 합니다. 어디까지 왔나 / 다음 한 걸음 / 목표 / 배운 것과 안 된 것 / 꼭 지킬 것. 못 하면 채웁니다.
6. **"됐다"마다 증거를 답니다.** 명령 결과, diff, 완성 기준 체크를 상태 문서의 "확인한 것"에 적습니다. "아마", "될 것"은 증거가 아닙니다.
7. 검사 도구가 있으면 돌리고, 커밋합니다.
8. 사용자에게 알립니다: 바뀐 것 3줄, 다음 세션 프롬프트, 사용자가 확인할 것 하나.
9. second_brain에 남길 교훈이 있으면 5장대로 합니다.

## 4. 프롬프트 모양

```
<프로젝트>의 CLAUDE.md대로 STATUS.md의 "지금"과 "다음 한 걸음"만 읽고,
<파일 + 장>만 열어 <할 일>을 해 줘. 멈출 곳: <…>.
시작 전에 이해한 계획을 10줄 이내로 보고해.
```

## 5. second_brain에 되돌려 쓰기

- **다른 프로젝트에도 통할 교훈**이 있을 때만 한 줄 남깁니다. 프로젝트에만 해당하는 숫자나 파일 이름은 일반화해서 씁니다. 비밀, 개인정보, 고객 정보는 쓰지 않습니다.
- **second_brain 레포(`tthwaghtt/second_brain`)가 push 가능하게 붙어 있으면**, 그 clone에서:
  ```bash
  python3 tools/add_note.py inbox --source "<프로젝트>/<세션>" --scope "<적용 범위>" \
      --what "<무엇>" --why "<왜>" --next "<다음엔>"
  git add inbox && git commit -m "inbox: <프로젝트> <한 줄 요약>" && git push
  ```
- **붙어 있지 않으면** 같은 내용을 끝 보고에 "second_brain inbox에 남길 한 줄"로 적습니다.
- 노트(`insights/` 등)와 스킬은 직접 고치지 않습니다. 그건 `brain-compile`의 일입니다.
