# project-board

> 판 1 · 2026-10-26 · 원본: PORTFOLIO `tools/board/`(커밋 6e5b6bd, 사용자 승인 10-26). 원본과 다른 곳은 `DIFF.md`.

목표: md로만 읽기 어려운 프로젝트 진행을, 문서와 git만 읽어 그림으로 보여 주는 현황판을 그 프로젝트에 세운다. 사용자가 파일의 구조와 역할을 파악해 스스로 지휘하게 하는 것이 궁극의 목적이다(현황판 `README.md` 7장).

사용자는 한국어만 읽는다. 보고는 한국어로, 쉬운 말로 한다. 명령 이름이나 경로는 그대로 두되 무엇을 하는지 한 줄로 풀어 쓴다.

## 0. 먼저 알 것

- **만드는 것은 `tools/board/` 하나다.** 그 프로젝트의 문서(규칙 파일, STATUS, MAP …)는 읽기만 한다. 문서를 고칠 일(MAP의 역할 표, 현황판 등록)은 5단계의 프롬프트로 그 프로젝트의 기획 책임 세션에 맡긴다. second-brain 프로젝트에서는 기획 책임 세션만 기준 문서를 고치기 때문이다.
- **설치·다운로드가 없다.** 파이썬 3.11 이상 표준 라이브러리만 쓰고, 글꼴(Pretendard, Courier Prime; OFL)은 스킬 안에 들어 있다. 무언가 설치해야 할 것 같으면 멈추고 묻는다.
- **멈추는 곳은 한 번이다:** 1단계 끝(계획과 디자인을 한 번에 물음). 사용자가 "명령 하나로 한번에" 만들기를 원했기 때문이다.
  - 사용자가 미리 답을 주었으면(예: "계획은 보고만 하고 진행", "디자인은 그대로") 5줄 보고만 보내고 바로 2단계로 간다.
  - 막지 않는 물음(커밋, 앱 안 브라우저 등록)은 멈추지 않고 6단계 끝 보고에 추천 답과 함께 모은다.
  - 문제가 생기면(문서 모양이 아예 다름, 덮어쓸 폴더가 있음) 그때만 멈추고 묻는다.
- **스킬 경로:** 이 파일이 있는 폴더(`~/.claude/skills/project-board/`, 원본은 second_brain `skills/project-board/`). 아래 `$SKILL`은 그 폴더다.

## 1. 살펴보고 묻기 (아무것도 쓰지 않음)

```bash
python3 $SKILL/scripts/setup_board.py scan <프로젝트 폴더>
```

- 나오는 것: 역할마다 찾은 문서와 다른 후보, 그 문서들의 머리 한 줄과 장 목록, `board.toml` 초안. 본문은 읽지 않는다(규칙 파일의 "건드리지 않는 것" 줄과 로드맵의 "쓸 파일" 줄만 읽음).
- 초안에서 확인할 것:
  - **문서 짝:** 다른 후보가 있으면 옛 폴더(`old/`, `archive/`) 것이 아닌지, 지금 쓰는 것인지 머리 줄로 판단한다. 기획서는 `BRIEF.md`가 없으면 `PLAN.md` 같은 다른 이름일 수 있다(판·정할 것·바뀐 결정 장이 있는 문서). 상태 문서는 `STATUS.md` 또는 `HANDOFF.md`.
  - **`# 짐작` 줄:** 기본 장 이름이 없어 비슷한 장을 고른 것. 장 목록을 보고 맞으면 `# 짐작` 주석을 지운다.
  - **없는 문서·장:** 주석으로 남은 줄은 그 칸이 비어 있다는 뜻이다. 괜찮다. 지어내지 않는다.
  - **잠긴 곳:** 규칙 파일의 "건드리지 않는 것"(장이든 한 줄이든)에서 뽑았다. 빠진 것이 있으면 그 부분만 읽어 더한다. 잠금은 현황판에서 옮기기·지우기를 막을 뿐, 내용을 고칠 권한과는 다르다.
  - **`[roles]`:** MAP에 역할 표가 생기기 전까지 역할을 짐작하는 곳이다. `user`(사용자 자료: "건드리지 않는 것" 폴더가 들어감), `work`(작업물: 로드맵 "쓸 파일"의 폴더가 들어감), `record`·`report`·`old`·`data`. 비어 있으면 그 프로젝트의 폴더 나무를 보고, 분명한 것만 채운다. 모르면 비워 둔다("분류 안 됨"으로 보이는 편이 틀린 역할보다 낫다).
  - **포트:** 프로젝트 이름으로 정해져(8791~8889) 프로젝트마다 다르다. install 때 그 번호를 다른 프로그램이 쓰고 있으면 다음 번호로 넘어가니, 보고에는 "8835 (바뀔 수 있음)"처럼 쓴다.
  - **git이 없으면:** 계획 변화·커밋→세션·바뀐 내용 화면이 빈다고 알린다.
  - **`tools/board/`가 이미 있으면:** 덮어쓰지 않는다. 무엇이 있는지 보고하고 어떻게 할지 묻는다(7장).
- 사용자에게 보고하고 묻는다. 보고는 짧게(5줄 안): 어디에 무엇을 만드는지, 찾은 문서, 없는 것, 포트. 질문은 AskUserQuestion 한 번에 두 개:
  1. **계획대로 세울까요?** → "네, 세워 주세요 (추천)" / "고칠 곳이 있어요"
  2. **현황판 디자인을 어떻게 할까요?** → "그대로 쓰기 (추천)": PORTFOLIO에서 승인한 디자인(엷은 미색 종이, 먹색 글자, 청색 하나, 노선도). 바로 씀. / "이 프로젝트에 맞게 다시 정하기": impeccable init → shape → design-taste 세 방향을 실제 데이터로 그려 고름. 세션 하나 크기이고, 그동안은 지금 디자인으로 씀.

## 2. 세우기

```bash
python3 $SKILL/scripts/setup_board.py install <프로젝트 폴더>     # --dest, --name, --port로 바꿀 수 있음
```

- `assets/board/`를 `<프로젝트>/tools/board/`로 복사하고 scan과 같은 초안을 `board.toml`로 쓴다.
- 1단계에서 확인한 것을 `board.toml`에 반영한다(Edit). 장 이름은 제목의 일부만 쓴다(번호는 빼고). 숫자만 쓰면 장 번호로 찾는다.

## 3. 맞추기 (`check.py`가 0 failed가 될 때까지)

```bash
cd <프로젝트 폴더> && python3 tools/board/check.py --docs
```

| 나온 것 | 뜻 | 고칠 곳 |
|---|---|---|
| `FAIL board.toml [headings] X = "…": … 에 그 장이 있음` | 그 문서에 그 장 이름이 없음 | 장 목록에서 맞는 제목을 찾아 고치거나, 없으면 그 줄을 주석으로 |
| `skip … 장이 없음` / `아직 없음` / `… 파일이 없음` | 그 문서나 장이 이 프로젝트에 없어 그 칸이 빔 | 고칠 것 없음. 이 목록이 곧 6단계의 "비어 있는 칸"이다. 경로를 잘못 적었는지만 확인 |
| `FAIL 로드맵에서 세션을 읽음` | 세션 머리 모양이 다름 | 로드맵이 `### S1. 제목` 모양인지 장 목록으로 확인. 모양이 아예 다르면 코드를 고치지 말고 사용자에게 보고 |
| `FAIL 읽는 길 …` | 규칙 파일의 세션 시작 장을 못 읽음 | `[headings] start`를 그 장 제목으로 |
| `FAIL 나무의 파일 수 …`, `파일 색인의 수 …` | 숨김 목록과 실제가 다름 | `[files] hidden` |
| `FAIL 지도 설명 … 없는 경로` | MAP 폴더 지도의 경로가 낡음 | 고치지 않는다. 5단계 프롬프트에 "폴더 지도의 낡은 경로"로 덧붙여 기획 책임 세션에 맡긴다 |

- 그다음 `python3 tools/board/check.py --ops`도 한 번 돌린다. 시스템 임시 폴더에 프로젝트를 복사해 그 안에서만 이름 바꾸기·옮기기·휴지통을 시험하므로 프로젝트는 그대로다.
- 켜서 본다: `python3 tools/board/server.py` → `http://127.0.0.1:<포트>`. 다섯 화면(1~5 키)을 다 열어, 비어 있는 칸이 문서에 정말 없는 것인지 확인한다.
  - 앱 안 브라우저로 보려면 `.claude/launch.json`에 "board" 항목을 더해야 하는데, 그 프로젝트의 설정 파일이므로 끝 보고에서 묻는다.
  - 브라우저 없이 볼 때(읽기만, 토큰 필요 없음): 개요·로드맵 `/api/state`, 계획 변화 `/api/history`, 파일 `/api/files`와 `/api/tree`, 찾기 `/api/search?q=낱말`과 `/api/glossary`. 다 보면 서버를 끈다.
  - 문서에는 있는데 화면에 안 나오는 것을 찾으면 현황판 코드를 고치지 말고 끝 보고에 적는다(스킬의 코드는 스킬에서 고치고 `DIFF.md`에 적는다, 7장).
- `board.toml`의 `[facts]`(지금 문서가 말하는 사실: 끝난 세션, 단계 1 순서, 기획서 판 …)는 고를 수 있다. 적어 두면 나중에 문서 모양이 바뀌어 파서가 틀릴 때 검사가 알려 준다. 사용자가 원하면 화면에서 확인한 값으로 적는다(키는 `check.py` 맨 위).

## 4. 디자인

- **그대로 쓰기:** 할 일 없음. 지금 디자인의 기록은 `references/design-system.md`(PORTFOLIO의 `DESIGN.md` 사본, 얼림)이고, 나중에 화면을 고칠 때 기준으로 읽는다.
- **다시 정하기:** `references/redesign.md`의 절차를 따른다. 세션 하나 크기라, 이 세션에서는 계획(plan-first)까지만 하고 실제 작업은 사용자가 원하면 새 세션에서 한다.

## 5. 역할 표 프롬프트 (그 프로젝트의 기획 책임 세션에 줄 것)

```bash
python3 $SKILL/scripts/setup_board.py prompt <프로젝트 폴더>
```

- 설치된 현황판으로 그 프로젝트의 지도 경로, 장 이름, 설명 없는 파일 목록, 문서 검사 명령을 채운 프롬프트를 만든다. 현황판 파일 화면의 "역할 표·설명 프롬프트 복사" 버튼과 같은 글에, 현황판 자신을 MAP에 등록하는 줄을 더한 것이다. 지도 문서가 없으면 먼저 만들고 `board.toml`에 적으라는 줄이 앞에 붙는다.
- 사용자에게 코드 블록으로 그대로 주고, 그 프로젝트의 기획 책임 세션(문서를 맡아 고치는 세션)에 붙여 넣으라고 한 줄로 안내한다. 이 세션이 대신 고치지 않는다(0장).
- 왜 필요한가: 역할 표가 없으면 현황판은 모든 파일의 역할을 "추정"으로 보인다. 표가 생기면 현황판이 저절로 읽어 "추정"이 사라진다.

## 6. 끝 보고

한국어로, 이 순서로:
1. 만든 것: `tools/board/`(코드 + `board.toml`), 프로젝트의 다른 파일은 그대로. `board.toml`에서 손본 곳
2. 켜는 법: `python3 tools/board/server.py` → 주소. "열지 못했습니다"가 나오면 `--port 8899`처럼 다른 번호를 붙인다는 것
3. 검사 결과: `--docs`, `--ops` 각각 ok·failed·skip 수
4. 비어 있는 칸과 이유: `check.py`의 skip 목록을 쉬운 말로. 문서에 없어서 비었다는 것
5. 문서에는 있는데 화면에 안 나오는 것(찾았을 때만)
6. 사용자가 할 일: 5단계 프롬프트(코드 블록), (다시 정하기를 골랐으면) 디자인 세션 시작
7. 물을 것(추천 답과 함께):
   - 커밋: 하지 않았다. 그 프로젝트의 커밋 규칙대로 묻고, 규칙이 없으면 "`tools/board/`만 골라 커밋 (추천)". 개요의 "커밋 안 된 변경 N개"는 대부분 새 현황판 파일이라 커밋하면 줄어든다는 것. `.state/`, `.trash/`는 `.gitignore`로 빠진다
   - 앱 안 브라우저 등록(`.claude/launch.json`): 사용자가 앱 안에서 보고 싶을 때만

## 7. 이미 현황판이 있을 때, 새 판 코드로 바꿀 때

- 이미 있는 `tools/board/`는 지우거나 덮어쓰지 않는다. `board.toml`, `.state/`(사용자의 "파악함"), `.trash/`(휴지통), `PRODUCT.md`, `DESIGN.md`, `.impeccable/`은 사용자 것이거나 그 프로젝트의 결정이다.
- 코드만 바꿀 때: `DIFF.md`로 판의 차이를 보이고, 사용자가 승인하면 `assets/board/`의 `server.py`, `check.py`, `board/`, `static/`만 바꾼다. 디자인을 다시 정한 프로젝트면 `static/`은 바꾸지 않고 묻는다. 바꾼 뒤 3단계를 다시 돈다.
- 스킬의 코드를 고쳤으면 `DIFF.md`에 적고 판을 올린다. PORTFOLIO 원본과의 차이를 한 곳에서 볼 수 있어야 다음 판을 옮길 때 길을 잃지 않는다.
