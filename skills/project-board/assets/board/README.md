# 현황판 (tools/board/)

> 기준 문서. 이 프로젝트의 md 문서와 git을 읽어 진행을 그림으로 보여 주는 로컬 웹 현황판입니다. project-board 스킬(second_brain `skills/project-board/`)이 세웠고, 처음 만든 곳은 PORTFOLIO의 `tools/board/`(2026-10-25, 승인 10-26)입니다. 이 프로젝트에서 디자인을 다시 정했다면 제품 기록은 `PRODUCT.md`, 디자인 기록은 `DESIGN.md`입니다.

## 1. 켜는 법

```bash
python3 tools/board/server.py
```

- 브라우저에서 `http://127.0.0.1:<포트>`를 엽니다. 포트는 `board.toml`의 `port`입니다. 끌 때는 터미널에서 Ctrl+C를 누릅니다.
- 앱 안 브라우저로 볼 때는 `.claude/launch.json`에 "board"를 등록해 씁니다.
- 파이썬 3.11 이상의 표준 라이브러리만 씁니다. 설치할 것도, 빌드할 것도 없습니다.
- 다른 포트나 다른 프로젝트를 볼 때는 `--port 8799 --root /경로`를 붙입니다.
- 검사: `python3 tools/board/check.py`
  - 실제 문서로 파서를 맞춰 봅니다(`--docs`). 이 프로젝트에 없는 문서나 아직 없는 장은 실패가 아니라 "skip"입니다.
  - 파일 조작은 임시 복사본에서만 시험합니다(`--ops`).

## 2. 화면 다섯 (단축키 1~5, 찾기는 /, 프롬프트 복사는 C)

| 화면 | 먼저 답하는 것 | 출처 (`board.toml` `[docs]`) |
|---|---|---|
| 개요 | 지금 하는 세션(없으면 다음 차례)과 멈출 곳, 그 세션의 읽는 길, 시작 프롬프트 복사, 정할 것과 마지막 사용자 원문, 노선도, 장부 한 줄(커밋 안 된 변경·마지막 커밋·문서 검사·계획 변화) | status, roadmap, rules의 세션 시작 장, brief의 정할 것, directions, git, `[check]` |
| 계획 변화 | 날짜 칸마다 방향, 기획서·로드맵의 판, 세션이 생김·끝남·중단, 사용자 원문 장, 커밋 수. 그 아래 바뀐 결정(옛 → 새) | old_index의 방향 표, git의 판, directions, brief의 바뀐 결정 |
| 로드맵 | 노선도(역을 누르면 고름), 단계별 세션 목록, 고른 세션의 모든 필드와 쓰는·읽는 파일, 세션 × 파일 표 | roadmap |
| 파일 | 역할 판(첫 보기)과 위치(나무). 살펴볼 것: 파악 진도, 설명 없는 파일(등록 프롬프트), 새 파일 검토함. 파일을 누르면 세 칸: 목록 · 파일 한 장(역할, 바뀌는 법, 누가 고치나, 가리키는 곳 양쪽, 커밋과 세션, 신선도, 파악함, 지시 조각) · 원문/바뀐 내용. 이름 바꾸기·옮기기·휴지통 | 파일 시스템, git, map의 폴더 지도와 "파일의 역할" 표 |
| 찾기 | 모든 문서·코드 본문 찾기(살아 있는 문서 먼저, 기록은 뒤), 용어 풀이(map의 "용어" 표 + 방법·현황판의 말) | 텍스트 파일, map |

- **없는 문서:** 그 화면이나 칸은 "이 프로젝트에는 X가 없습니다"처럼 비워 둡니다. 지어내지 않습니다.
- **노선도:** 세션은 역이고, 로드맵의 "전제"는 선로입니다.
  - 전제가 갈라지면 선로도 갈라집니다(예: 두 갈래가 나란히 가다가 한 세션에서 만남).
  - 전제가 적히지 않은 세션은 앞 단계 끝에 점선으로 잇습니다. 문서에 없는 갈래를 지어내지 않습니다.
  - 역을 누르면 그 세션의 목표·할 일·멈출 곳이 뜹니다.
- **새로 고침:** 3초마다 바뀐 것이 있는지 묻고(파일 수정 시각 + git), 바뀌었으면 다시 그립니다. 열린 창(설명 창, 문서 창, 확인 창)이 있으면 닫힌 뒤에 그립니다.

## 3. 무엇을 어떻게 읽나 (`board.toml`)

`board.toml`에는 문서 위치, 장 이름, 역할을 짐작할 곳, 잠긴 곳만 적습니다. 사실(단계, 세션, 결정)은 문서에만 있습니다. 파서는 second-brain 문서 규칙에 기댑니다.

| 규칙 | 예 | 읽는 곳 |
|---|---|---|
| 판·날짜·상태 머리 | `> 기준 문서 · 판 7 · 2026-10-25 · 상태: **승인 10-25**` | `board/roadmap.py` `header()` |
| 단계 장 | `## 단계 1. 1차 공개 (약 2주)` | `roadmap.parse()` |
| 세션 머리, 끝남 | `### S3. 제목 — 완료 10-25`, 역할은 끝 괄호 `(웹, 일꾼 세션)` | `roadmap.SESSION` |
| 세션 필드 | `- 전제:`, `- 목표:`, `- 할 일:`(번호 목록), `- 멈출 곳:`, `- 쓸 파일:`, `- 읽을 것:`, `- 완성 기준: - [ ] …(확인: …)` | `roadmap.fields()` |
| 한 줄 세션 | `- S6. 제목` (먼 단계) | `roadmap.ONE` |
| 바뀐 결정 | `~~옛~~ (출처) → 새 (날짜, 출처)` | `docs.split_steps()` |
| 정할 것 | `1. **제목:** 내용`, 기한은 상태 문서 "정할 것이 있는 곳"의 "S2 전까지" | `docs.brief()`, `docs.deadlines()` |
| 지금 하는 세션 | 상태 문서 "진행 중인 세션" 표의 상태가 "진행 중…"인 줄 | `server.running_ids()` |
| 다음 세션 | 상태 문서 "다음 세션 시작 프롬프트" 장의 `> 작성 날짜 · 다음: S2` 줄과 코드 블록 | `docs.status()` |
| 사용자 원문 | `## 10. 2026-10-24 제목` | `docs.directions()` |
| 파일의 역할 | 지도 문서 "파일의 역할" 표 `\| 경로 \| 역할 \| 바뀌는 법 \| 누가 고치나 \| 무게 \|` (무게: 지휘·작업·참고·기계). 없으면 `[roles]`의 곳과 규칙으로 짐작해 "추정" | `board/index.py` `map_roles()`, `GUESS` |
| 읽는 길 | 규칙 파일 세션 시작 장의 `doc_section.py` 명령 순서(없으면 그 장이 이름으로 적은 문서 순서) + 세션의 "읽을 것" | `index.reading_path()` |
| 커밋 → 세션 | 커밋 메시지의 첫 세션 번호(`이름 S1 …`) | `index.commits_by_file()` |
| 방향 | old_index의 기간·방향 표 | `docs.old_directions()` |
| 파일 설명 | 지도 문서 "폴더 지도"의 나무 줄 | `board/tree.py` `descriptions()` |

**거짓으로 보이지 않게 지킨 것:**
- 끝남은 세션 머리의 "완료"로만 봅니다. 완성 기준의 체크박스는 세션마다 쓰는 법이 달라서, 네모는 적힌 그대로 보여 주되 진행 막대로 세지 않습니다.
- 문서에 "진행 중"이 없으면 "다음 차례 (상태 문서 기준)"로만 씁니다.
- 계획 변화는 기획서·로드맵의 지금 경로의 git 기록만 따라갑니다. 옛 판을 다른 폴더로 옮겼다면, 그것까지 따라가면 같은 커밋을 두 번 셉니다.
- 커밋된 적 없는 판은 "커밋된 적 없음"으로 비워 둡니다.
- 읽지 못한 것은 추측하지 않고 원문 창으로 보여 줍니다.

## 4. 파일 조작의 안전 (`board/ops.py`)

- 127.0.0.1에서만 엽니다. Host 머리를 확인합니다.
- 쓰기 요청은 아래를 모두 갖춰야 받습니다: 같은 출처, JSON, 화면에 심은 실행마다 새로 만드는 토큰.
- 경로:
  - 프로젝트 안의 실제 경로만 다룹니다. 절대 경로, `..`, `~`, 링크는 거절합니다.
  - 폴더를 자기 안으로 옮기는 것을 막습니다.
  - 문서를 이름으로 찾는 곳(`[docs] search`) 안에 같은 이름의 문서가 생기는 것을 막습니다.
- 잠긴 곳(`board.toml` `[[files.locked]]`)과 그것을 품은 폴더는 보이기만 합니다.
- 옮기기는 `git mv`가 아니라 그냥 옮깁니다. 다른 세션이 골라 담는 커밋에 반쯤 섞이지 않게 하려는 것입니다. 이름이 바뀐 것은 git이 커밋할 때 알아봅니다.
- 삭제는 `.trash/<시각-id>/`로 옮기고 원래 경로·크기·해시를 적습니다. 되살릴 때 해시를 맞춰 봅니다.
- "파악함"은 `.state/understood.json`(이 컴퓨터에만, git에 담지 않음)에 파일의 수정 시각과 함께 적습니다. 파일이 바뀌면 "다시 볼 것"이 됩니다. 쓰기 요청은 파일 조작과 같은 토큰·출처 검사를 거칩니다.
- 화면이 마지막으로 본 수정 시각과 다르면(다른 세션이 그사이 고침) 거절합니다.
- 확인 창이 보여 주는 것:
  - 대상, 가리키는 곳 N군데(기록 문서 속 것은 따로)
  - 경고: 커밋 안 된 변경, 10분 안에 바뀜, 상태 문서의 진행 중인 세션이 쓰는 곳, 스테이징됨
  - 조작이 끝나면 문서 검사를 다시 돌려 결과를 보여 줍니다.
- 하지 않는 것: 파일 내용 고치기, 새 파일, 커밋·올리기, 문서 속 경로 자동 고치기

## 5. 이 프로젝트에 맞추기

1. 문서가 옮겨지거나 장 이름이 바뀌면 `board.toml`의 `[docs]`·`[headings]`를 고치고 `python3 tools/board/check.py --docs`가 0 failed인지 봅니다.
2. 현황판이 맞게 보이면, 지금 문서가 말하는 사실을 `board.toml`의 `[facts]`에 적어 둘 수 있습니다(끝난 세션, 단계 1의 세션 순서, 기획서 판 …; 모두 고를 수 있음, 키는 `check.py` 맨 위). 나중에 문서 모양이 바뀌어 파서가 틀리게 읽으면 검사가 알려 줍니다. 코드를 새 판으로 바꿔도 `board.toml`은 남으므로 사실도 남습니다.
3. 파일의 역할은 지도 문서의 "파일의 역할" 표에 한 번만 적습니다. 현황판은 읽기만 하고, 적는 일은 기획 책임 세션이 합니다(파일 화면의 "역할 표·설명 프롬프트 복사").
4. 새 판의 현황판 코드로 바꿀 때는 스킬 폴더의 `DIFF.md`를 보고, `board.toml`·`.state/`·`.trash/`는 남깁니다.

## 6. 만든 과정에서 배운 것 (PORTFOLIO, 2026-10-25)

- 디자인 순서: impeccable init → shape → design-taste app-screens 방향 3개(실제 데이터로 첫 화면만 그려 나란히 보임) → 구현 → lint·inspect --app → impeccable critique·audit·polish → 마감 검토 → DESIGN.md
- impeccable은 `--target tools/board/`를 주면 이 폴더를 프로젝트로 보고 `PRODUCT.md`를 여기서 찾습니다. 주지 않으면 맨 위 PRODUCT.md(프로젝트 본체의 것)를 씁니다.
- design-taste가 고른 글꼴(Public Sans)에는 한글이 없습니다. 한글 화면은 Pretendard를 쓰고 검사기의 `font-not-dealt`를 이유와 함께 허용합니다.
- 시작 프롬프트 원문의 "★"처럼 문서에서 온 기호는 바꾸지 않고, `emoji` 검사를 이유와 함께 허용합니다.
- 숨겨진 창에서는 animation frame과 ResizeObserver가 멈춥니다. 노선도는 타이머로도 한 번 그립니다.
- 로드맵의 체크박스는 세션마다 다르게 쓰여 진행 표시로 믿을 수 없습니다. "완료" 머리만 믿습니다.

## 7. 처음 만들 때 정한 것 (PORTFOLIO 사용자 결정, 2026-10-25)

목표(사용자 원문 요약): 파일들의 구조와 각각의 역할을 사용자가 모두 파악해서, 주체성을 가지고 프로젝트를 지휘하게 한다.

- 디자인: AI 티가 나지 않게. 그라디언트·글로우·무지개 차트·지어낸 수치·카드 속 카드 금지, 실제 데이터만 씀
- 창은 전체 화면 기준(반쪽 창에서는 한 줄로 쌓여 깨지지 않게만). 다크 모드에서는 맥을 따라 숯검정 판
- 파일의 역할과 "누가 고치나"는 지도 문서에 한 번만 적습니다. 지도에 아직 없는 파일은 현황판이 규칙에서 짐작해 "추정"으로 표시합니다.
- 읽는 길은 규칙 파일의 세션 시작 장을 그대로 읽어 그립니다(따로 적지 않음).
- "파악함" 표시는 사용자의 진도이지 프로젝트의 사실이 아니므로, 이 컴퓨터의 `.state/`(git에 담지 않음)에만 둡니다.
- 현황판의 자물쇠(옮기기·지우기를 막음)와 "누가 고치나"(내용을 고칠 세션)는 다른 표시와 다른 말로 나눕니다.
- 역에서: 개요는 누르면 설명 창, 로드맵 화면은 누르면 그 역을 고르고 아래에 전체 설명. 읽는 길은 카드의 세션 것("읽은 길" / "읽을 길")
