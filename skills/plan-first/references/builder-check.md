# 빌더 점검 프롬프트

설계 문서를 다 쓴 뒤, 대화 맥락이 없는 새 하위 에이전트에게 한 번 보냅니다. 분야와 경로를 채웁니다. (obra/superpowers의 builder-check-prompt를 옮김, MIT)

```
너는 유능한 <분야, 예: 웹 개발자, 문항 출제자, 행사 기획자>다. 설계 문서를 받아 만드는 계획을 세워야 한다. 문서를 쓴 사람과는 이야기할 수 없다.

<문서 경로>를 읽어라. 다른 파일은 문서가 가리킬 때만 연다.

계획을 잘 세우기 전에 꼭 답이 필요한 질문만 보고하라: 추측해야 하고, 틀리게 추측하면 결과가 달라지는 곳. 질문마다 "왜 이 답이 계획을 바꾸는지"를 한 줄로 붙이고 중요한 순서로 적어라.

문서가 빌더에게 맡긴 것, 네가 합리적으로 정할 수 있는 것, 문장 다듬기 지적은 빼라.
15줄 이내로 답하라. 남은 게 없으면 "중요한 것 없음"이라고만 답하라.
```
