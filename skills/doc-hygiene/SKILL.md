# doc-hygiene: 한 사실은 한 곳, 낡은 것은 남기지 않는다

**왜:** 세션을 갈아타며 일할 때 가장 위험한 것은 틀린 정보보다 **맞았던 정보가 낡은 채 남은 것**입니다. 그럴듯한 오답이 되어 다음 세션이 그걸 믿고 일합니다.

## 1. 한 사실은 한 곳

- 사실마다 기준 문서를 하나 정합니다. 다른 문서는 "파일 + 장"으로 가리키기만 합니다(예: "지금 상태는 `STATUS.md` 2장").
- 문서 이름은 겹치지 않게 짓고, 장 번호(`## 3.`, `### 3-2.`)를 붙이고, 참조는 "파일 + 장"으로 씁니다. 그러면 참조가 곧 읽기 명령이 됩니다.

## 2. 문서는 고치는 법으로 네 종류

| 종류 | 고치는 법 | 예 |
|---|---|---|
| 흐름 | 매번 덮어씀 | 상태 문서 |
| 기준 | 고쳐 쓰고 바뀐 날짜를 적음 | 설계, PRD, 로드맵 |
| 기록 | 끝에 덧붙이기만 | 사용자 원문, 결정 기록 |
| 보고서 | 그날 결과로 얼림. 틀린 곳은 머리에 정정 메모 | 조사·점검 보고서 |

- 한 문서에 종류를 섞으면 한쪽이 반드시 낡습니다. 예: 상태 문서 안에 결정 표를 복사해 두면, 결정이 바뀔 때 복사본이 남습니다.
- **규칙 파일(CLAUDE.md)** 에는 지금 단계, 늘 지킬 원칙, "일 → 문서의 장 → 코드" 찾아가기 표만 둡니다. 200줄 아래로 둡니다. 요약을 두면 "요약, 기준은 X"라고 밝힙니다. 사람만 볼 메모는 `<!-- -->` 주석으로 씁니다.
- 옛 판, 보관, 백업은 읽는 길에서 빼고 규칙 파일에 "따르지 말 것"이라고 표시합니다.
- 새 설계 문서 머리에는 "초안, 승인 전"을 둡니다. 사용자에게 물을 것은 문서 끝 "정할 것" 장 한 곳에만 둡니다.

## 3. 결정이 바뀔 때

1. 사용자 원문을 날짜와 함께 원문 기록에 덧붙입니다.
2. 기준 문서를 고칩니다. 옛 결정은 지우지 않고 `~~옛 결정~~ → 새 결정(날짜)`으로 남깁니다.
3. **바뀐 낱말과 숫자로 프로젝트 전체를 검색합니다**(`grep -rn "옛값\|옛 용어"`). 나온 자리마다 이렇게 합니다.
   - 기준 문서면 고칩니다.
   - 복사본이면 가리키기로 바꿉니다.
   - 기록이나 보고서면 그대로 둡니다.
   - 그 결정을 기다리던 문구("적용 대기", "사용자가 정함", "S1 보고 때")는 지웁니다. **가장 자주 놓치는 단계입니다.**
4. 다음 세션 프롬프트에 영향이 있으면 고칩니다.
5. 보고에 "바꾼 곳 / 그대로 둔 곳(왜)"을 적습니다.

## 4. 크게 바꾼 뒤 점검 (읽기만)

- **찾을 것:** 겹침(같은 내용 두 곳), 모순(값이 다름), 낡은 표현, 용어 표류(같은 것을 다른 이름으로), 애매함.
- **심각도:** 다음 세션이 틀리게 일할 수 있으면 높음 / 헷갈림이면 중간 / 모양 문제면 낮음.
- 보고서로 먼저 보고하고, 고치는 건 승인 뒤에 합니다.

## 5. 파일·폴더 옮기기

옮기기 전에 `references/reorganize.md`를 읽습니다. 핵심은 이렇습니다: 먼저 커밋, `git mv`, 조각 경로까지 검색, 실제로 실행해 확인.
