# 끝 검사

> reverse-prompt 7장에서 엽니다. 되짚기에 도하가 "맞다"고 하고, 소프트웨어면 그림 미리보기를 승인한(또는 건너뛴) 뒤, 넘길 문서를 다 쓰기 전에 합니다. 2판(2026-11-24)에서 sorbh판의 "찾은 것 요약 먼저, 작은 것은 한꺼번에"를 되돌림.

**왜:** 인터뷰한 AI는 대화를 다 알아서, 문서에 빠진 것을 못 봅니다. 앞 대화를 모르는 새 AI가 문서만 읽고 막히는 곳이 곧 다음 세션이 도하에게 다시 물을 곳입니다.

## 1. 준비

- 스펙 초안을 설계 문서 틀(`~/.claude/skills/plan-first/references/design-doc.md`)로 새 프로젝트 폴더에 씁니다. `handoff-docs.md` 2장의 꼭 둘 장(결정 표, 의존 관계와 만드는 순서, 소프트웨어면 구조)을 넣고, 미리보기에서 승인한 그림의 mermaid 원본도 그 장들에 넣습니다. 결정 표가 있어야 공격 읽기가 이미 답한 것을 다시 올리지 않습니다.
- 새 맥락 서브에이전트에게 아래 두 가지를 시킵니다. 따로 보내도 되고 한 번에 보내도 됩니다. 서브에이전트가 없으면 내가 그 빌더처럼, 대화 기억은 쓰지 않고 문서만으로 읽습니다.
- 상태 파일의 `finalCheck.status`를 `in-progress`로 적습니다.

## 2. 빌더 점검

`~/.claude/skills/plan-first/references/builder-check.md`의 프롬프트를 씁니다. 분야는 그 프로젝트를 만들 사람(예: 웹 개발자, 영상 자동화 개발자)으로 채웁니다.

## 3. 공격 읽기

공격 읽기는 새 AI가 설계의 약한 곳을 일부러 찾는 점검입니다. 분야와 경로를 채워 보냅니다.

```
너는 이 설계를 공격하는 검토자다. 분야는 <분야>다. 문서를 쓴 사람과는 이야기할 수 없다.
<스펙 경로>를 읽어라. 다른 파일은 문서가 가리킬 때만 연다. 결정 표에 이미 답이 있는 것은 다시 올리지 마라.

이 프로젝트에 해당하는 갈래만 보라:
- 실패하는 경우: 오류, 중간에 끊김, 시간 초과
- 커질 때 무너지는 곳: 사용자·데이터·호출이 늘 때
- 보안 빈틈: 로그인과 권한, 개인정보, 비밀값, 입력을 그대로 실행함
- 서로 부딪히는 결정
- 운영: 고장을 어떻게 아나, 되돌릴 수 있나
- 데이터가 꼬이는 곳: 동시에 고침, 지우지 않고 쌓임
- 남의 도구에 기대는 위험: 가격 변경, 약관, 서비스 중단
마지막에 "다 정한 뒤에도 무엇이 틀어질 수 있나"를 한 번 더 보라.

찾은 것마다 적어라: 제목 한 줄, 갈래(위 목록 가운데 어느 것), 무엇이 문제인지, 근거(문서의 어느 장), 심각도(큼·중간·작음), 문서를 쓴 사람에게 물을 질문 하나와 선택지 2~4개.
심각한 순서로 20줄 이내. 남은 게 없으면 "중요한 것 없음"이라고만 답하고, 본 갈래와 가장 튼튼한 곳, 가장 아슬아슬했던 곳을 한 줄씩 덧붙여라.
```

## 4. 돌아온 것 풀기

1. **요약 먼저.** 하나씩 묻기 전에, 빌더 점검과 공격 읽기에서 돌아온 것을 번호 목록으로 보여 줍니다: 번호, 제목, 심각도, 갈래(빌더 점검에서 온 것은 "빌더"). 도하가 몇 개를 답해야 하는지 먼저 알게 하려는 것입니다. 상태 파일의 `finalCheck.findings`에 같은 목록을 적습니다.
2. **세 무더기로 나눕니다.**

   | 무더기 | 할 일 |
   |---|---|
   | 이미 답이 있음 | 문서에 그 답을 분명히 씁니다. 빌더가 못 찾았다면 문서가 모자란 것입니다 |
   | 도하만 답할 수 있음 | 큰 것부터, 그다음 중간 것을 인터뷰처럼 하나씩, 추측 답을 붙여 묻습니다. 보안 문제는 도하가 답하거나 위험을 받아들인다고 말하기 전에는 스펙을 마치지 않습니다 |
   | 작은 것 | 큰 것과 중간 것을 다 푼 뒤, 한 질문으로 묶어 묻습니다(아래) |

3. **작은 것은 한꺼번에.** 질문 하나에 남은 작은 것의 번호와 제목을 다 보여 주고 고르게 합니다.
   - AI가 정하고 결정 표에 "내 판단"으로 적음(추천)
   - 정하지 않고 "알고 넘김(작음)"으로 결정 표에 남김
   - 기타 칸에 따로 볼 번호를 적음(그 번호만 하나씩 묻습니다)

   보안 문제는 작아 보여도 이 묶음에 넣지 않습니다.
4. **찾은 것이 하나도 없으면** 깨끗하게 알립니다: 본 갈래, 가장 튼튼한 곳, 가장 아슬아슬했던 곳.
5. **결정 표에 적기:** 끝 검사에서 정한 줄은 출처를 "끝 검사"로 씁니다. 누가 정했는지(도하 / 내 판단)도 씁니다.
6. **두 묶음으로 요약합니다.** 다 풀면 결과를 두 묶음으로 보여 줍니다.
   - 도하가 답한 것: 질문과 도하의 답
   - AI가 정하거나 짐작한 것: "내 판단"으로 정한 것, 묶어 넘긴 것, 알고 넘긴 것

   고칠 곳은 대개 두 번째 묶음에 있습니다.

- 도하만 답할 수 있는 질문이 0개가 되면 상태 파일의 `finalCheck.status`를 `done`으로 적고 `handoff-docs.md`로 갑니다.
- 답을 받아 결정이 크게 바뀌었으면 끝 검사를 한 번 더 하고, 미리보기도 같은 주소에 다시 올립니다.
