# 그림 미리보기와 고치기 (소프트웨어)

> reverse-prompt 6장에서 엽니다. 되짚기 6줄에 도하가 "맞다"고 하고, 다음 단계로 미리보기를 고른 뒤에 씁니다. sorbh판(sorbh/interview-me)의 미리보기 단계와 그 그림 규칙 파일(`STYLE_PRESETS.md`)에서 필요한 것만 골라 다시 씀(MIT). 색과 코드 모양은 가져오지 않음.

**왜:** 6줄 되짚기는 의도를 맞춥니다. 그런데 AI가 머릿속에 그린 제품 모양(구조, 흐름, 화면)은 글 6줄로는 보이지 않습니다. 도하가 그 모양을 그림으로 보고 다른 곳을 고쳐야, 도하의 의도와 맥락이 AI와 맞습니다(도하의 말, `FEEDBACK.md` 2026-11-21). 그림에서는 글에서보다 틀린 곳이 빨리 보입니다.

## 1. 무엇을 그리나

인터뷰에서 나온 것만 그립니다. 나오지 않은 덩어리나 화면을 지어내 그리지 않습니다.

| 인터뷰에서 나온 것 | 그릴 그림 |
|---|---|
| 구조(어디서 돌아가나, 큰 덩어리) | 덩어리 흐름: 화면 → 서버 → 저장소. 바깥 도구(남의 API, 결제 등)는 점선 |
| 사용자가 하는 일 | 사용자 흐름: 왼쪽에서 오른쪽으로, 갈림길은 마름모 |
| 데이터 | 데이터 흐름: 어디서 들어와 어디에 쌓이고, 언제 지워지나 |
| 실패하는 경우 | 갈림 그림: 잘 되는 길은 가운데, 실패하는 길은 아래로 갈라져 빨간 선 |
| 화면(있으면) | 화면 목록과, 화면마다 무엇이 어디에 놓이나(대강의 칸 배치) |
| 의존 관계와 만드는 순서 | 층으로 나눈 의존 그림: 아무것에도 기대지 않는 층이 왼쪽, 화살표는 늘 오른쪽으로 |

## 2. 페이지 짜임 (세 단계로 훑게)

도하는 세 단계로 훑습니다. 10초 동안 맨 위와 한눈에 칸을, 1분 동안 그림과 장마다 한 줄 요지를 보고, 더 보고 싶은 곳만 긴 글을 읽습니다.

1. **맨 위:** 이름, 한 줄 요약, "검토용 초안", 날짜.
2. **한눈에 칸 3~4개:** 문제(왜), 만드는 방법, 도구, 가장 큰 위험. 한 줄씩, 아주 짧게.
3. **어떻게 돌아가나:** 늘 첫 장이고, 늘 큰 흐름 그림이 하나 있습니다.
4. **주제마다 한 장:** 한 줄 요지 → 그림(흐름이나 구조가 있을 때) → 2~5문장. 그림이 없는 주제는 짧은 글이나 표로 씁니다.
5. **결정 표:** 접어 둡니다.
6. **만드는 순서:** 의존 그림과 순서 목록.

- **AI가 짐작한 부분은 표시합니다.** 되짚기의 "AI가 짐작한 것" 묶음에 든 것은 그림과 글에 "짐작" 표시를 붙입니다. 고칠 곳은 대개 거기 있습니다.
- 페이지는 읽는 문서입니다. 입력 칸이나 단추를 만들지 않습니다.

## 3. 만드는 법

- 페이지는 Artifact 도구로 올립니다. Artifact 도구의 페이지 규칙(밝은 화면과 어두운 화면, 휴대폰 폭)을 따르고, 도하에게 보이는 글은 plain-words 스킬대로 씁니다.
- **그림은 mermaid로 그립니다.** 페이지 안에서 바로 그려집니다. mermaid로 안 되는 그림만 inline SVG로 그립니다. 그림 속 글자는 짧게(1~3낱말) 쓰고, 설명은 그림 밖 글에 씁니다.
- **mermaid 원본(그림을 만드는 글)을 지우지 않습니다.** 승인되면 그 원본을 설계 문서에 옮깁니다(이 파일 4장).
- 파일은 임시 폴더(scratchpad)에 둡니다. 올린 주소는 상태 파일의 `preview.url`과 설계 문서 머리에 적습니다.
- Artifact 도구가 없으면 같은 내용을 온전한 HTML 파일로 임시 폴더에 쓰고 `open`으로 엽니다. 도하에게 파일 위치를 알립니다.

### Figma로 그릴 때 (도하가 고를 때만)

- 화면처럼 손으로 옮기며 고치는 게 나은 것은 도하가 원하면 Figma로 그립니다. 나머지 그림은 페이지에 둡니다.
- Figma 도구를 쓰기 전에 Figma 스킬(`figma:figma-use`, 화면 전체면 `figma:figma-generate-design`도)을 먼저 엽니다.
- 순서: AI가 Figma에 대강의 화면 배치를 그림 → 도하가 Figma에서 옮기고 고침 → AI가 도하가 고친 것을 읽고(`get_design_context`, `get_screenshot`) 미리보기 페이지와 결정 표에 반영함.
- Figma에 연결할 수 없으면(인증이 필요하다고 나오는 등) 도하에게 알리고, 화면도 페이지에 그립니다.

## 4. 고치기 고리

1. 페이지 주소를 한 줄로 알리고, "고칠 곳을 채팅이나 페이지 댓글로 알려 주세요"라고 씁니다.
2. 도하가 고칠 곳을 말하면 고칩니다. 뜻이 두 가지로 읽히면 질문 1~2개로 묻습니다(SKILL.md 2장처럼 하나씩).
3. 같은 파일 경로로 다시 올려 같은 주소를 지킵니다. 무엇을 고쳤는지 한 줄로 알립니다.
4. 도하가 분명히 승인할 때까지 되풀이합니다. "좋아요"는 승인이 아닙니다. "고칠 곳 있나요?"라고 묻습니다.
5. 고친 것은 결정 표에 출처 "미리보기"로 적습니다. 고치다가 의도(6줄)가 바뀌면 SKILL.md 5장 되짚기로 돌아갑니다.
6. 승인되면 상태 파일의 `preview.status`를 `approved`로 고칩니다. 승인한 그림의 mermaid 원본과 Figma 주소는 SKILL.md 7장에서 스펙 초안을 쓸 때 설계 문서의 구조 장, 화면 장 같은 곳에 넣습니다(`handoff-docs.md` 2장). 다음 세션은 페이지가 아니라 설계 문서를 읽기 때문입니다.

- 끝 검사(SKILL.md 7장)에서 결정이 바뀌면 같은 주소에 다시 올려 마지막 모양을 보여 줍니다.
- 도하가 미리보기를 건너뛰면 상태 파일의 `preview.status`를 `skipped`로 적고 SKILL.md 7장 끝 검사로 갑니다.
