# brain-compile: inbox 메모를 노트와 스킬로 정제한다

**왜:** 세션들은 inbox에 쓰기만 하고 읽지 않습니다. 그래서 inbox는 정제하지 않으면 쓸모가 없습니다. 이 일을 따로 여는 세션에서 하면, 다른 작업의 맥락을 오염시키지 않고 비용도 한 번만 듭니다.

## 1. 준비

1. `tthwaghtt/second_brain`을 push 가능하게 붙이고 clone합니다.
2. `INDEX.md`와 `inbox/*.md`만 읽습니다. 노트 본문은 아직 열지 않습니다.
3. 옮기지 않은 줄(끝에 `→ 옮김`이 없는 줄)이 몇 개인지 셉니다.

## 2. 묶고 정하기

1. 같은 교훈끼리 묶습니다. 묶음마다 정합니다.
   - **기존 노트에 더함:** INDEX의 한 줄 요약으로 대상 노트를 찾고, 그 노트의 해당 장만 엽니다.
   - **새 노트:** 같은 주제의 노트가 없을 때만 만듭니다.
   - **보류:** 한 번만 나온 프로젝트 사례는 `lessons/`에 "무엇 / 왜 / 다음엔"으로만 넣습니다.
2. 계획 표(묶음 / 대상 / 할 일 / 근거 줄)를 사용자에게 보여 주고 승인을 받습니다.

## 3. 쓰기

- 손으로 고치지 않고 `python3 tools/add_note.py`(`new`, `append`, `index`)로 고칩니다. 그래야 노트와 INDEX가 어긋나지 않습니다.
- 틀린 것으로 드러난 내용은 지우지 않고 `~~취소선~~`과 날짜, 이유를 남깁니다.
- 옮긴 inbox 줄 끝에는 `→ 옮김: <노트> (날짜)`를 붙입니다.
- **두 번 이상 확인된 규칙만 스킬에 반영합니다**(`skills/<이름>/`). 고친 스킬은 `second-brain` 판 날짜를 올립니다. 스킬 본문은 짧게 두고, 길어지면 그 스킬의 `references/`로 뺍니다.

## 4. 끝

1. `python3 tools/add_note.py check` 문제 0 → 커밋 → push.
2. 사용자에게 알립니다: 옮긴 줄 수, 바뀐 노트, 바뀐 스킬.
3. 스킬이 바뀌었으면 다시 설치하라고 안내합니다. 맥은 링크라서 저절로 따라가고, 클라우드는 다시 패키지해서 저장해야 합니다.
