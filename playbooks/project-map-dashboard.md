# 프로젝트 지도 대시보드 만들기 (구조 + 실시간 작업 + 일대기)

> 날짜: 2026-10-16 · 출처: MAGNUM OPUS `project/map/` (원본 코드, 커밋 b6ef763·4f4cbf8) · 근거: 경험 · 태그: 지도, 대시보드, 주체성, 토큰, 실시간
> **규칙:** 사람용 지도는 폴더 상자 지도에 마우스를 올릴 때만 선을 보이고, 대화 기록은 읽기만 합니다. · **적용 범위:** 큰 코드 프로젝트(MAGNUM OPUS급). 작은 프로젝트에는 과함

사용자가 "이 프로젝트가 어떻게 생겼고, Claude가 지금 무엇을 하고, 전체에서 어디까지 왔는지"를 한 화면에서 보게 하는 로컬 웹 페이지. Claude의 토큰은 0(따로 돌고, Claude는 화면을 읽지 않음). 같은 데이터로 Claude도 `query.py`로 파일 연결을 물어 탐색을 줄임.

## 2. 짜임 (파이썬 표준 라이브러리 + 손으로 쓴 HTML/CSS/JS, 외부 라이브러리 0)

```
map/
├─ build.py    지도 데이터(map/data/map.json, git 밖): 노드(파일·문서 장·데이터 폴더) + 선(imports, calls, writes, reads, points)
├─ server.py   127.0.0.1 전용 서버: /api/map, /api/sessions, /api/events?s=, /api/live(SSE), /api/file?p=, /api/progress
├─ query.py    Claude용 조회: python3 map/query.py act1_take.py | DESIGN.md 4-5 | render/layout | --find 낱말
├─ page/       index.html, style.css, map.js
└─ README.md   여는 법, 화면 읽는 법, 알아 둘 점
```

- **build.py:** 코드 분석은 프로젝트의 `codemap.py`(파일 목적·함수·import·데이터 쓰기/읽기), 장은 `doc_section.py`의 `headings()`를 재사용. 지도 자체 파일과 "모든 것을 나열하는 색인 문서(CODEMAP.md)"는 연결에서 뺌(잡음).
- **server.py:** 원천 파일이 지도 데이터보다 새로우면 `/api/map` 때 다시 만듦. `/api/live`는 가장 최근에 쓰인 세션 기록을 0.4초마다 이어 읽어 SSE로 보냄(새 세션이 생기면 갈아탐). 처음 붙을 때 마지막 300개를 한꺼번에 보냄.
- **query.py:** 같은 `map.json`에서 답함. Claude 규칙 파일에 "파일을 찾거나 고치기 전에 query.py로 연결을 먼저 본다"를 넣음.

## 3. 대화 기록(JSONL)을 사건으로 바꾸는 규칙

- 기록 위치: `~/.claude/projects/<경로를 -로 바꾼 키>/<세션 id>.jsonl`. 세션을 연 폴더마다 키가 다름(저장소 맨 위, 하위 폴더). 비슷한 이름의 **다른 프로젝트 폴더(예: `-MOTION`)는 빼야** 함. 백업 폴더도 함께 훑고 같은 id는 살아 있는 쪽 우선.
- 줄 종류: `assistant`(content: text / thinking / tool_use), `user`(문자열이면 사람의 말, 목록이면 도구 결과), `custom-title`(세션 이름), 줄마다 `timestamp`, `cwd`. `isSidechain`은 빼기.
- **생각 내용은 기록에 없음**(`thinking`은 빈 문자열 + 서명). "생각하는 중…"만 보여 주고, 사용자에게 미리 말함.
- 도구별: Read(경로, offset/limit → 줄 범위 → 문서면 장), Edit/Write(고침), Grep/Glob(찾기), Bash(아래), update_plan(작업 목록 상태를 따라가 "i/n 단계"), wrap_up(요약을 말로).
- **Bash 판정:** 명령을 줄과 토큰으로 쪼개 지도 노드에 맞는 경로·고유한 파일 이름을 찾음. `python3/bash/sh/zsh/node/-P` 바로 뒤나 `./x.sh`는 실행, 같은 줄에 `sed -i`, 리다이렉트 `>`, `open(…'w')`, `git mv`, `cp`, `mv` 등이 있으면 고침, 나머지는 읽음. `doc_section.py 문서 장`은 그 장 읽음. 파이썬 히어독의 `p='경로'`는 고침.
- 경로는 절대 경로, 그 줄의 `cwd` 기준, 프로젝트 기준, `project/` 접두를 뗀 꼴 순으로 맞춰 봄. 출력 폴더 안의 파일은 그 데이터 칸으로.

## 4. 일대기 띠 (어디까지 왔나)

- 원천은 사람이 이미 쓰는 두 문서: 로드맵의 "큰 그림" 표(단계 | 세션 범위 | 내용)와 상태 문서의 "다음 세션: Sx". `S1~S6`은 S1..S6으로 펴고, `S20~`처럼 끝이 열린 것은 한 칸.
- 세션 이름은 로드맵 머리(`### S2. …`)나 표의 행(`| S10 | …`)에서. 다음 세션보다 앞 = 끝남, 같음 = 다음 차례, 뒤 = 남음.
- 별도 진행 파일을 만들지 않음(한 사실은 한 곳에만). 인수인계 때 상태 문서만 고치면 띠가 따라감. 주기적 다시 읽기(15초)로 "실시간".

## 5. 새 프로젝트에 옮길 때 바꿀 것

1. 서버의 대화 기록 키 목록과 백업 폴더(프로젝트 경로에서 만들어짐).
2. build.py의 묶을 데이터 폴더(`render/`, `logs/` 같은 출력), 건너뛸 폴더, 분야 색 매핑(최상위 폴더 이름).
3. 일대기: 로드맵 표의 열 순서, 세션 이름 꼴(S/W/F 접두).
4. 코드 분석기(codemap)와 장 읽기(doc_section)를 함께 가져옴. 없으면 build.py에서 파일 목록·줄 수만 먼저.
5. 앱 브라우저 칸에 띄우려면 **세션을 여는 폴더**의 `.claude/launch.json`에 `{name: "map", runtimeExecutable: "python3", runtimeArgs: ["map/server.py","--port","5190"], port: 5190}`. 다른 폴더에서 연 세션은 못 찾음 → 서버를 직접 띄우고 `http://localhost:5190`.

## 6. 만드는 순서 (한 세션 안에서)

1. 사용자에게 화면 그림(ASCII)과 "생각 내용은 안 보임"을 먼저 보여 주고 승인.
2. 기록 형식 확인: 최근 세션 JSONL에서 줄 종류와 tool_use 예시를 세어 봄.
3. build.py → `python3 map/build.py`로 노드·선 수 확인, query.py로 표본 한 파일의 연결이 맞는지(지도 자체 파일이 데이터를 "만든다"고 나오면 잡음).
4. server.py → 세션 목록과 한 세션의 사건 개수·종류를 파이썬으로 바로 찍어 봄.
5. 페이지 → 브라우저에서 실시간(이 세션의 사건이 바로 뜨는지), 마우스 올림(선), 누름(오른쪽 칸), 다시 보기(240배)를 실제로 확인.
6. 지도 README, 규칙 파일의 찾아가기 표, 상태 문서에 한 줄씩. 코드 지도 다시 만들고 문서 검사 0개.

## 7. 주의와 판단

- **처음 판(힘 그래프 + git 시간 막대)은 사용자가 갈아엎게 함.** 점이 수백 개면 뭉쳐서 "구조"가 안 읽힘. 폴더 상자 지도는 구조가 한눈에 읽히고, 연결은 마우스를 올릴 때만 선으로 → 이쪽을 기본으로.
- 화면 그림(ASCII)으로 설계를 먼저 보여 주고 승인받은 뒤 만들었더니, 사용자가 그 설계를 기준으로 첫 판을 갈아엎게 할 수 있었음(설계와 구현이 어긋날 때 판단 기준이 됨).
- 서버는 대화 기록을 **읽기만**, 127.0.0.1에서만. 인터넷으로 아무것도 보내지 않음.
- 지도 작업 범위를 `map/` 안으로 묶어 달라는 요청이 나옴 → 밖(규칙 파일, 코드 지도, 원문 기록)을 고쳐야 하면 먼저 보고.
- 자동 판정의 틀림과 그때의 삽질은 `lessons/mistakes.md` 14~17.
