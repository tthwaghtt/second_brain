# 새 프로젝트를 0부터가 아니라 여기서부터 시작하기

> 날짜: 2026-10-16 · 출처: MAGNUM OPUS에서 쌓은 방식 · 근거: 경험 · 태그: 시작, 인수인계, 구조
> **규칙:** 새 프로젝트는 작게(CLAUDE.md + HANDOFF.md) 시작하고 커지면 나눕니다. 처음부터 지킬 습관 7가지만 지킵니다. · **적용 범위:** 모든 새 프로젝트

## 1. 시작 프롬프트 (새 프로젝트의 첫 세션에 붙여 넣기)

> ~/MY_PROJECT/second_brain/INDEX.md를 읽고, playbooks/new-project-kickoff.md와 playbooks/handoff.md만 열어 이 프로젝트에 맞게 적용해 줘. templates/의 CLAUDE.md, HANDOFF.md, USER_DIRECTIONS.md를 프로젝트에 맞게 고쳐 만들고, 이 프로젝트에 맞지 않는 부분은 빼거나 바꾼 이유를 보고해. 만들기 전에 계획을 먼저 보고해.

## 2. 프로젝트 크기에 따라 고르기

| 크기 | 만들 것 |
|---|---|
| 작음 (세션 몇 개) | `CLAUDE.md`(짧게) + `HANDOFF.md` 하나 |
| 중간 | + `USER_DIRECTIONS.md`(원문) + 설계 문서 하나(`DESIGN.md`) |
| 큼 (세션 수십 개, MAGNUM OPUS급) | + `docs/` 폴더 나누기(`insights/doc-structure.md`), `ROADMAP.md`(세션마다 전제·목표·읽을 것·할 일. 시작 프롬프트는 두지 않음 → 상태 문서 한 곳), `STATUS.md`(HANDOFF 6항목 포함), 코드 지도와 문서 검사 도구(`insights/file-index-tools.md`), 제작 기록 |

처음부터 큰 틀을 다 만들지 않습니다. 커지면 그때 나눕니다(폴더 정리는 `playbooks/reorganize-folders.md`).

## 3. 첫 세션에서 정할 것 (사용자에게 묻기)

- 프로젝트 목적, 1순위 기준(예: MAGNUM OPUS는 "압도감, 품질 타협 없음")
- 보고 언어, 승인 지점(무엇은 묻고 무엇은 바로 해도 되나)
- 건드리면 안 되는 파일과 폴더, 작업하는 폴더
- 비밀(키)은 어디 있나 → 출력·붙여넣기 금지
- 세션 단위: 한 세션에 무엇까지

## 4. 처음부터 지킬 습관 (나중에 고치면 비쌈)

1. 한 사실은 한 곳에만. 원문은 원문 기록에만.
2. 문서에 장 번호(`## 3.`, `### 3-2.`), 참조는 "파일 + 장".
3. 문서 이름은 겹치지 않게.
4. 규칙 파일 200줄 이하.
5. 계획의 숫자는 코드로 확인, 추정은 "추정"이라고.
6. 세션 끝마다 HANDOFF + 커밋 + second_brain 한 줄.
7. 안 쓰는 연결(MCP)은 꺼 두기(단, 앱 전체 기본값이 바뀜).

## 5. 이 프로젝트에 맞게 바꿀 것

MAGNUM OPUS 방식은 렌더·블렌더·웹이 섞인 큰 작품용입니다. 코드가 거의 없는 글쓰기 프로젝트라면 코드 지도는 빼고, 웹 앱이라면 데이터 지도 대신 API·컴포넌트 지도가 낫습니다. 바꾼 이유는 그 프로젝트의 `CLAUDE.md`에 한 줄 남기고, 일반화할 만하면 second_brain에도.
