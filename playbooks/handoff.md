# 인수인계 플레이북 (세션을 새로 열 때)

> 날짜: 2026-10-16 · 출처: MAGNUM OPUS `docs/session/HANDOVER.md` + 사용자가 공부한 HANDOFF 6항목 · 근거: 경험 · 태그: 인수인계, 세션
> **규칙:** 세션을 닫기 전에 원문 기록 → 기준 문서 → 상태 문서(HANDOFF 6항목 + 다음 세션 프롬프트) → 검사 → 커밋 순으로 남깁니다. · **적용 범위:** 다음 세션이 이어받는 모든 프로젝트

## 1. 기본 틀: HANDOFF 6항목 (사용자가 공부한 것)

1. Goal (목표)
2. Current state (지금 상태)
3. Active files (지금 손대는 파일)
4. Changes made (바뀐 것)
5. Failed attempts (안 된 시도)
6. Specific next step (구체적인 다음 한 걸음)

→ 틀: `templates/HANDOFF.md`. 작은 프로젝트는 이 파일 하나로 충분합니다.

## 2. MAGNUM OPUS에서 더해 효과 본 것 (프로젝트가 커지면)

| 더한 것 | 왜 | 어디에 |
|---|---|---|
| **사용자 원문 기록** (날짜 + 말씀 그대로) | 결정의 근거. 새 세션이 대화 기록을 뒤지지 않음 | `USER_DIRECTIONS.md` |
| **다음 세션의 시작 프롬프트** | 사용자는 붙여 넣기만. "이해한 계획을 먼저 보고해" 포함. 작성 날짜·세션·승인 원문 출처를 함께. ~~로드맵의 세션마다~~(10-16 바꿈) | **상태 문서 한 곳에만**, 다음 할 일이 정해질 때마다 갱신(`insights/context-consistency.md` 5장) |
| **읽을 것 목록 (장 단위)** | 새 세션이 탐색하지 않음. 토큰 절약의 핵심 | 로드맵 세션 항목 "읽을 것" |
| **열린 결정 표** | 사용자가 정할 것, 언제, 근거 | 설계 문서의 한 장(상태 문서는 가리키기만, 10-16 바꿈) |
| **알려진 문제 표** | 언제(어느 세션) 고치나 | 상태 문서 |
| **세션 로드맵** | 남은 일을 세션 단위로 쪼갬. 세션 하나 = 목표 하나 | `ROADMAP.md` |
| **돌고 있는 작업** | 렌더·서버 등이 돌고 있으면 새 세션이 겹쳐 실행하지 않게 | 상태 문서 |
| **확인한 것** | "됐다"는 말 대신 무엇으로 확인했는지 | 상태 문서 |
| **제작 기록(토큰·시간)** | 무엇이 효과 있었는지 숫자로 | 자동 스크립트 |

## 3. 닫기 전 체크리스트 (세션 끝마다)

1. 사용자 원문(결정, 피드백)을 날짜와 함께 원문 기록 끝에 덧붙임
2. 결정이 바뀌었으면 기준 문서(설계 문서)를 고침. 규칙 파일 요약이 틀어지면 함께
3. 상태 문서를 새로 씀: HANDOFF 6항목 + 알려진 문제 + 다음 세션 시작 프롬프트(날짜·세션·승인 원문 출처). 열린 결정은 설계 문서의 한 장에만(상태 문서는 가리키기). 결정이 바뀌었으면 `insights/context-consistency.md` 9장의 "결정이 바뀔 때"
4. 코드를 바꿨으면 코드 지도 갱신, 문서 검사 0개 확인, 제작 기록 실행
5. 커밋하고 원격에 올림(메시지에 무엇을, 왜)
6. 대화 기록 백업(`~/.claude/projects/<프로젝트 키>*/`를 별도 폴더로)
7. 사용자에게 다음 세션 시작 프롬프트를 알려 줌
8. **second_brain에 이번 세션의 인사이트·삽질을 한 줄이라도 더함** (→ `INDEX.md`)

## 4. 새 세션 열 때 (Claude가 할 일)

1. 규칙 파일(자동) → 상태 문서의 "지금" 장 → 로드맵의 그 세션 항목 → 그 항목의 "읽을 것" 장만
2. 확인: 최근 커밋, 작업 갈래, 돌고 있는 작업, (렌더가 있다면) 전원
3. 이해한 목표와 계획을 짧게 보고하고, 승인이 필요하면 기다림
