# 사용자 목표 다섯 갈래와 그 방법

> 날짜: 2026-10-16 · 출처: MAGNUM OPUS (사용자 목표: "주체성과 높은 이해도, 토큰 절약, 컨텍스트 오염과 파일 꼬임을 줄여 의도대로 최대 성능의 결과물") · 근거: 제안(대부분 아직 적용 전) · 태그: 목표, 주체성, 의도, 품질
> **규칙:** 맡기면서도 주인으로 남으려면 사람용 지도, 결정 번호, 잴 수 있는 완성 기준을 먼저 둡니다. · **적용 범위:** 사용자가 결정을 쥐고 Claude가 실행하는 모든 프로젝트(대부분 아직 적용 전인 제안)

사용자가 Claude에게 맡기면서도 프로젝트의 주인으로 남고 싶을 때 쓰는 방법들입니다. 어느 프로젝트에나 거의 그대로 씁니다.

## ① 주체성과 이해도 (사용자가 구조를 알고, 결정을 쥠)

- **사람용 지도:** 폴더 상자와 파일 칸, 연결선, Claude가 지금 읽는/고친 파일이 실시간으로 빛남, 지난 세션 다시 보기, 전체 일대기 띠. 외부 라이브러리 없이 로컬 페이지로, 앱 옆 브라우저 칸에 띄움(2026-10-16 만듦 → `playbooks/project-map-dashboard.md`).
- **결정 카드(D-번호):** 결정마다 번호, 원문(날짜, 말씀 그대로), 담긴 문서 장, 구현된 코드 줄. 커밋에 번호를 적어 "말 → 문서 → 코드"를 추적.
- **세션 끝 3줄 요약:** 무엇이 바뀌었나, 왜(D-번호), 사용자가 확인할 것 하나. git 변경에서 자동으로.
- **짧은 보고 형식:** 결론 → 바뀐 것 → 확인할 것. 읽는 부담과 출력 토큰이 함께 줄어듦.

## ② 토큰 절약
→ `token-economy.md`. 여기에 더해: Claude도 그래프 조회 도구로 곧장 가기, 대화 길이 눈금(상태 줄)으로 정해 둔 선을 넘으면 인수인계.

## ③ 컨텍스트 오염 방지
→ `context-hygiene.md`. 한 세션 한 목표, 원문 한 곳, 큰 로그는 파일로, 별도 세션은 꼭 필요할 때만.

## ④ 파일 꼬임 방지

- **커밋 전 자동 검사(git 훅):** 문서 검사와 코드 지도 갱신을 커밋마다 돌리고 어긋나면 멈춤. 저장소 설정을 바꾸므로 사용자 승인 필요.
- **고치기 전 영향 확인:** 그래프의 "이걸 바꾸면 영향 받는 것"을 먼저 보고 보고서에 적음.
- 작은 단위 커밋, 결정 번호 함께.
- 큰 옮기기는 `playbooks/reorganize-folders.md` 절차대로.

## ⑤ 의도대로, 최대 성능으로

- **완성 기준을 먼저:** 세션 시작 전에 잴 수 있는 기준을 적고 승인받음(예: "미완성 노출 0, 감속 최대 3.5 g 이하, 이 3장면을 정지 화면으로"). 끝은 말이 아니라 검사 결과와 화면으로.
- **계획은 코드와 대조한 뒤에 확정:** 계획서 숫자를 실제 코드로 다시 계산하니 틀린 값이 여럿 나왔음(→ `lessons/mistakes.md`). 계획 세션의 마지막 단계는 "코드와 대조".
- **눈으로 승인:** 숫자만이 아니라 캡처 시트·미리보기로 사용자가 직접 보고 승인.
- **조사 결과는 따로 검증:** "직접 확인했다"는 조사서도 22곳 중 2곳이 틀렸고 파일 경로 오기가 있었음. 외부 사실(리포 별 수, 라이선스, 기능)은 별도 확인 후 씀.
