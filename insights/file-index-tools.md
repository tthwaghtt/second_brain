# 파일 지도(인덱스)와 도구로 꼭 필요한 것만 읽기

> 날짜: 2026-10-16 · 출처: MAGNUM OPUS (`scripts/docs/`) · 근거: 경험 · 태그: 지도, 인덱스, 도구, 토큰
> **규칙:** 탐색 대신 지도를 씁니다. 문서는 장 단위로, 코드는 자동 생성 지도의 줄 번호로 필요한 부분만 읽고, 지도가 낡았는지는 검사 도구로 잡습니다. · **적용 범위:** 코드와 문서가 많은 중간 이상 프로젝트

## 1. 지도 세 겹

| 지도 | 담는 것 | 언제 읽히나 |
|---|---|---|
| 규칙 파일(`CLAUDE.md`) 머리와 찾아가기 표 | 문서가 어느 폴더에 있나, "이 일 → 문서의 몇 장 → 어느 코드(함수)" 12줄 | 세션마다 자동 |
| 인수인계 문서의 폴더 나무 | 폴더 전체 그림(문서, 코드, 데이터, git 밖 폴더) | 폴더가 헷갈릴 때 |
| 코드 지도(`CODEMAP.md`, 자동 생성) | ① 작품 순서별 파일 ② 코드 파일마다 목적·줄 수·함수와 줄 번호·부르는 파일 ③ 데이터 폴더마다 만드는 코드와 읽는 코드(`파일:줄`) | 코드를 찾을 때 |

찾는 순서(예: "종탑 시각 고치기"): 찾아가기 표 → `DESIGN.md` 4-5와 `act1_take.py`의 `_hall_beats` → 문서는 그 장만, 코드는 지도의 줄 번호(449) 근처만 읽음. `ls`·`grep`·통째 읽기가 거의 없어짐.

## 2. 도구 세 개 (파이썬 표준 기능만)

| 도구 | 하는 일 | 이 저장소 |
|---|---|---|
| `doc_section.py <문서> <장>` | 문서의 장 하나를 **빠짐없이 통째로** 꺼냄(다음 같은 단계 제목까지). `--list`로 장 목록. 문서 이름만 주면 `docs/` 아래에서 찾음 | `tools/doc_section.py` (일반판) |
| `codemap.py` | 코드 폴더를 **스스로 훑어**(정해 둔 목록이 아니라) 코드 지도를 만듦. 머리말 첫 줄, 최상위 함수와 줄 번호, import, 코드에 적힌 데이터 경로와 쓰기/읽기 판정 | 설명만(프로젝트마다 다름) |
| `doc_check.py` | ① 없는 장을 가리키는 참조 ② 없는 파일 경로(문서와 코드 속 문자열 모두) ③ 같은 숫자가 원본(편집표)과 다른 곳 ④ 코드 지도가 코드보다 오래됐는지 | 설명만 |

## 3. 효과와 주의

- 장 단위로 **통째로** 읽기 때문에 잘라 읽다 빠뜨리는 일이 없습니다(품질 유지). "필요한 것만"의 단위는 장입니다.
- 사람이 쓰는 지도는 금방 낡습니다. 코드 지도는 반드시 **자동 생성**, 그리고 검사 도구가 "지도가 코드보다 오래됨"을 잡게.
- 검사 도구는 처음 돌리자 실제 문제를 찾았습니다(없어진 장 "계획서 6·9장", 옛 경로). 세션을 닫을 때마다 돌립니다.
- 검사 도구의 거짓 경보(외부 리포 안 경로, 앞으로 만들 파일, 스크립트가 쓰는 출력 파일)는 예외 목록·"신설" 표시로 처리.
- 데이터 쓰기/읽기 자동 판정은 그 줄에 `open("w")`, `save`, `--out` 같은 말이 있는지로 하므로 틀릴 수 있음 → `파일:줄`을 함께 적어 확인 가능하게.
