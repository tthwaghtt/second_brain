# 문서를 구조화하는 법 (찾기 쉽고, 모순이 안 생기게)

> 날짜: 2026-10-16 · 출처: MAGNUM OPUS 10-15 문서·폴더 정리 · 근거: 경험 · 태그: 문서, 구조, 모순
> **규칙:** 한 사실은 한 곳에, 문서에는 장 번호, 참조는 "파일 + 장", 문서 이름은 겹치지 않게 씁니다. · **적용 범위:** 문서가 여러 개인 프로젝트

## 1. 한 사실은 한 곳에만 (가장 중요)

같은 결정이 다섯 문서에 반복되어 있었고, 실제로 그중 세 곳이 서로 다른 값(종탑 완공 시각 30.5 / 30.3 / 31.2초)을 갖고 있었습니다. 고칠 때 한 곳만 고치면 반드시 어긋납니다.

| 종류 | 기준 문서(여기만 고침) | 다른 문서는 |
|---|---|---|
| 결정과 설계 값 | 설계 문서(`DESIGN.md`) | "파일 + 장 번호"로 가리키기만 |
| 지금 상태, 다음 세션 | 상태 문서(`STATUS.md`) | 결정을 되풀이하지 않음 |
| 적용 계획 | 계획 문서 | 적용이 끝나면 "적용됨 → 설계 문서 몇 장" |
| 기술, 렌더, 예산 | 기술 문서(`PIPELINE.md`) | |
| 사용자 원문 | 원문 기록(`USER_DIRECTIONS.md`) | 헷갈릴 때만 읽음 |

규칙 파일(`CLAUDE.md`)에는 "지금 단계, 늘 지킬 원칙, 어디를 보나 표"만 둡니다. 요약이 틀어질 때만 고칩니다.

## 2. 폴더로 묶기

맨 위에 문서 13개가 섞여 있던 것을 목적별로 묶었습니다.

```
docs/
├─ session/   STATUS, ROADMAP, HANDOVER      ← 세션 운영
├─ design/    DESIGN, INTERACTION, WEB       ← 작품 설계 (결정의 기준)
├─ tech/      PIPELINE, RUNPOD_SETUP         ← 기술
├─ plan/      FEEDBACK_V6_PLAN               ← 적용 계획
├─ research/  조사 보고서
├─ record/    USER_DIRECTIONS, MAKING_STATS  ← 원문과 기록
└─ CODEMAP.md                                ← 코드 지도 (자동)
```

- **문서 이름은 겹치지 않게** 짓습니다. 그러면 본문에서 경로 없이 이름만 써도 되고(`DESIGN.md` 4-7), 도구가 이름으로 찾습니다. 폴더를 옮겨도 본문 참조를 고칠 필요가 없습니다.
- 규칙 파일(`CLAUDE.md`)과 소개(`README.md`)는 맨 위에 둡니다(자동으로 읽히는 자리).
- 스크립트도 목적별: `scripts/docs`(문서 도구), `pipeline`(렌더·인코딩), `look`(시험), `check`(검사), `previs`(미리보기 페이지), `make`(재료 생성).
- 폴더 이름은 영어로(명령어와 경로에서 다루기 쉬움). 설명은 지도에 한국어로.

## 3. 장 번호로 가리키기

- 문서는 `## 4.`, `### 4-7.` 처럼 장 번호를 붙여 씁니다. 참조는 늘 "파일 + 장"(`DESIGN.md` 4-7). 그러면 참조가 곧 읽기 명령이 됩니다(→ `file-index-tools.md`).
- 옛 판을 일부러 가리킬 때는 "(10-11 판 기준)"처럼 표시해 검사 도구가 건너뛰게 합니다.

## 4. 규칙 파일 줄이기

- 공식 권장 200줄 이하. 자동으로 매 응답에 실리므로 줄인 만큼 모든 응답이 가벼워집니다.
- 옮길 때 **지우지 않고 대조**합니다: 규칙 파일의 핵심 문구 40개를 설계 문서에서 하나씩 찾아, 없던 것만 옮김(그래서 정보 손실 0).

## 5. 초안과 확정을 구분

- 새 설계 문서는 머리에 "초안, 승인 전"을 박고, 사용자가 답한 것만 "확정" 표시. 결정이 아닌 것을 결정처럼 쓰지 않습니다.
- 사용자에게 물을 것은 문서 끝 "정할 것" 장에 모읍니다.

- 문서가 시간이 지나며 서로 어긋나는 것을 막는 법(문서 네 종류, 결정의 생애, 검사)은 `context-consistency.md`.
