# 토큰은 어디로 새고, 어떻게 아끼나

> 날짜: 2026-10-16 · 출처: MAGNUM OPUS (`docs/record/MAKING_STATS.md`, Claude Code 공식 비용 문서) · 근거: 측정 + 공식 문서 · 태그: 토큰, 세션, 캐시

## 1. 가장 큰 원인: 긴 세션의 "다시 읽기" (측정)

Claude는 응답할 때마다 **대화 전체를 다시 읽습니다**(캐시로 싸게 읽지만 쌓임). 도구를 한 번 쓸 때마다 또 한 번 읽습니다.

| MAGNUM OPUS 세션 | 응답 수 | 응답 1회당 다시 읽은 양(평균) | API 환산 |
|---|---|---|---|
| 첫 세션 (4일 동안 열어 둠, 작업 34시간) | 2,259 | 약 56만 토큰 | $429.71 |
| 둘째 세션 | 688 | 약 46만 토큰 | $126.73 |
| 짧게 끊은 세션 | 42 | 약 20만 토큰 | $4.60 |

- 첫 세션 비용의 약 60%가 다시 읽기(캐시 읽기 12.7억 토큰 × 백만당 $0.2)였고, 제가 쓴 출력은 약 16%뿐이었습니다.
- **결론:** 아끼는 첫째 방법은 파일 조작이 아니라 **세션을 짧게 끊는 것**입니다(→ `context-hygiene.md`).

## 3. 세션마다 읽는 양 줄이기

- **세션 시작 읽기 목록:** 문서 다섯 개를 통째로 읽던 것(약 9만 자)을 "상태 문서의 '지금' 장 → 로드맵의 그 세션 항목 → 그 항목이 적은 장"만 읽게 바꿈(→ `file-index-tools.md`).
- **장 단위 읽기:** 문서는 장 하나씩, 큰 코드는 함수 줄 번호로 그 부분만.
- **출력 걸러 받기:** 로그·검사 결과는 `tail`/`grep`, 이미지는 여러 장을 한 시트로.
- **탐색 대신 지도:** 파일 지도(인덱스)를 두면 `ls`·`grep`·"일단 열어 보기"가 거의 없어짐.

## 4. 작업 방식

- 일의 무게에 맞는 모델과 노력 수준: 기계적인 일은 Sonnet(별도 세션)이나 낮은 노력 수준, 설계 판단만 큰 모델(공식 문서 권장). 단, 사용자가 원할 때만.
- 별도 세션과 알림은 비용이 큼: 별도 세션이 끝나면 원래 세션이 **대화 전체를 들고** 다시 깨어남. 꼭 필요할 때만.
- 1시간 넘게 쉰 뒤 같은 세션을 이어 쓰면 캐시가 만료되어 대화 전체를 다시 저장함(공식 문서). 쉬었으면 새 세션.
- `/compact`도 대화 전체를 한 번 읽음. 이어 갈 필요가 없으면 새 세션이 더 쌈.
- 한국어는 같은 내용의 영어보다 토큰이 더 드는 편(정확한 비율은 재지 않음, 추정). 사람이 읽어야 하는 문서는 한국어로 두되 짧게 씀.

## 5. 측정 습관

- 세션마다 토큰·비용을 기록하는 스크립트를 돌려 누적합니다(MAGNUM OPUS의 `scripts/docs/making_stats.py`: `~/.claude/projects/<프로젝트>*/` 대화 기록에서 셈). 숫자가 있어야 무엇이 효과 있었는지 압니다.
