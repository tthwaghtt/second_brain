# 삽질 모음 (원인과 다시 안 하는 법)

> 날짜: 2026-10-16 · 출처: MAGNUM OPUS 10-15~16 · 근거: 경험 · 태그: 실수, 검증, git, 경로
> **규칙:** 숫자·좌표·경로는 머리로 계산하지 말고 코드를 실행해 확인합니다. 파일을 옮기기 전에는 커밋합니다. · **적용 범위:** 각 항목의 "다음엔"이 일반 규칙이고, 사례(종탑 시각, 각도, 경로 이름 등)는 MAGNUM OPUS 한정

새 삽질은 아래에 같은 꼴로 더합니다: **무엇 / 왜 / 다음엔.**

## 계획과 문서

1. **계획서 숫자가 코드와 달랐다.**
   - 무엇: "첨탑 30.3초 완공, 3.2초 동안 보임"이라 썼지만 코드에서 첨탑은 탑 일정 끝보다 1.6초 늦게 끝나 실제는 31.9초, 1.6초였음. 같은 값이 문서마다 30.5 / 30.3 / 31.2로 셋.
   - 왜: 코드를 돌려 보지 않고 머리로 계산. 같은 값을 여러 문서에 따로 씀.
   - 다음엔: 계획의 숫자는 코드로 계산해 확인(`python3 -c "import ...; print(beats())"`), 값은 한 문서에만.
2. **방향(부호)을 거꾸로 잡았다.** 엔딩 복귀 각도를 `α + 180°`로 써서 섬이 중심 섬 뒤로 감. 섬 위치와 카메라가 같은 방위 규칙(x = sin, y = cos)을 쓰는지 코드에서 확인했어야 했음. → 좌표·각도는 그 코드의 규칙을 먼저 읽기.
3. **방위 이름이 틀렸다.** 좌표는 맞는데 "북쪽/서쪽" 이름이 틀림(코드 머리말이 "x는 남북, 남쪽이 −x"). → 좌표계 규칙을 규칙 파일 찾아가기 표에 한 줄로 박아 둠.
4. **계산하지 않은 숫자를 썼다.** "18 g 이하", "+$4~6", "웹 증가 0 MB". → "측정 전 추정"이라고 표시하고, 잴 세션을 적기. 지어낸 수치 금지.
5. **조사서의 "직접 확인"이 다 맞지는 않았다.** 라이선스 없는 리포를 "퍼블릭 도메인", 없는 파일 경로, 리포에 없는 수식을 리포의 것처럼. → 외부 사실은 별도 검증 세션(GitHub API, 원본 파일)으로 확인.
6. **계산의 전제가 빠졌다.** "어느 각도에서나 일곱 섬이 다 보인다"가 섬 크기와 가림을 빼고 한 계산. 기존 106°는 2°마다 찾아 고른 각도였다(코드 주석). → 코드 주석에 "찾아 고른 값"이라 적혀 있으면 그 조건을 깨는지부터 의심.

## 파일 옮기기와 git

7. **일괄 치환이 이어 붙인 경로를 놓쳤다.** `"scripts/x.py"` 같은 문자열은 고쳤지만 `ROOT / "scripts" / "render.sh"`, `os.path.join(ROOT, "scripts", "camera_audit.py")`는 놓침(4곳). 실행해 보고서야 발견. → 옮긴 뒤 `"scripts"` 같은 **조각 문자열**도 검색, 그리고 실제로 실행해 봄. 검사 도구가 코드 속 경로도 확인하게.
8. **`git stash` / `stash pop`이 스테이징된 이름 바꾸기를 풀었다.** 옮기기 전 동작과 비교하려고 stash했더니 rename 75개가 "삭제 + 새 파일"로 풀림(내용은 무사, 커밋 때 다시 rename으로 잡힘). → 옮기는 중엔 stash하지 말고, 비교가 필요하면 먼저 커밋.
9. **파일 위치 계산이 폴더 깊이에 묶여 있었다.** `ROOT = parent.parent`가 한 단계 깊어지면 틀림. → 옮긴 뒤 모든 `ROOT` 식을 실행해 프로젝트 폴더가 나오는지 자동 확인(`exec` 한 줄 검사).
10. **코드 지도가 정해 둔 폴더 목록만 훑었다.** 새 폴더는 지도에서 빠짐. → 폴더를 스스로 훑게.

## 도구와 설정

11. **앱의 연결 끄기가 전역 기본값을 바꾼다.** 이 세션에서 끈 연결이 다른 프로젝트 새 세션에서도 꺼짐. → 끄기 전에 사용자에게 알림.
12. **별도 세션 알림이 비싸다.** 별도 세션이 끝나면 원래 세션이 대화 전체를 들고 다시 깨어남. → 꼭 필요할 때만, 사용자가 원할 때만.
13. **두 세션이 같은 문서를 고칠 뻔했다.** 구조를 바꾸는 중에 조사서 정정 세션을 제안함 → 철회. → 같은 파일을 두 세션이 동시에 고치지 않게.

## 지도 대시보드 (2026-10-16)

14. **`2>&1`을 "파일을 고쳤다"로 읽었다.** 명령에 `>`가 있으면 고침으로 판정했더니 표준 오류 돌리기(`2>&1`, `>/dev/null`)까지 걸림. → 리다이렉트는 숫자·`&` 뒤가 아니고 `/dev/null`·`&`로 가지 않을 때만 쓰기로 봄.
15. **지도 자신이 데이터를 "만든다"고 나왔다.** 지도 코드가 `render/`, `logs/` 같은 이름을 들고 있어서 데이터 쓰기/읽기 분석에 걸림. 모든 파일을 나열하는 색인 문서(CODEMAP.md)도 선을 수백 개 만듦. → 도구 자신과 색인 문서는 연결 분석에서 뺌.
16. **세션을 연 폴더가 달라 앱의 미리 보기 설정을 못 찾았다.** `.claude/launch.json`은 `project/`에 있는데 세션은 그 위 폴더에서 열려 있었음. → 서버를 직접 띄우고 `localhost` 주소로 열기. 규칙대로 세션을 `project/`에서 열면 해결.
17. **고친 지 얼마 안 된 지도 파일이 작업 폴더에서 지워져 있었다(누가 지웠는지 기록 없음).** → 지우기 전 상태가 커밋되어 있어 `git restore`로 되살림. 큰 작업은 끝나면 바로 커밋.
